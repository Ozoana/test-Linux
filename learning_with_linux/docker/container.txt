#container
ada yang nama nya itu container manager, container manager itu tidak sama dengan docker yah, ibarat nya docker itu alat sedangkan container manager itu konsep nya
container manager itu fungsi nya untuk membuat container dan di dalam nya itu sudah terisolasi jadi seperti punya habitat nya sendiri, misal aplikasi kita perlu python versi 1.2 sedangkan di leptop B dia punya python versi 1.3, jadi aplikasi nya tidka bisa berjalan di leptop B
nah di situ konsep container manager hadir. 
lalu container ini dia menggunakan yang nama nya itu sistem operasi host, jadi dia akan berjalan dimana container manager nya berjalan, misal container di buat di linux yang dimana container manager nya berada di linux itu, maka dia akan menggunakan sistem operasi linux tersebut, jadi tidak perlu lagi instal sistem operasi
vm atau virtual mesin, ini cukup mirip dengan itu tpi beda nya, untuk virtual mesin kita perlu instal sistem operasi lagi di dalam nya.
jadi semisal kita membuat 2 atau 3 vm, kita perlu instal lagi sistem operasinya apa dan lain nya. 
ditambah vm itu besar, bisa beberapa gb karena kalian perlu instal sistem operasi lagi di dalam nya(misal kita pake linux kali, terus di virtual mesin kita pake sistem operasi linux ubuntu, atau mau di isi windows), sedangkan untuk container, dia akan lebih sedikit, karena dia hanya perlu mem-packages aplikasi dan dependency nya (depedency itu seperti komponen apa saja yang di perlukan, atua bisa di bilang dia ketergantungan dengan banyak hal, bukan berdiri sendiri itu lah depedency), tidak harus sistem operasinya
